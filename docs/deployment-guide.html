2. Run it locally (development)

The development server reloads the page automatically whenever you save a file. Use it while editing content.

  1. Open a terminal in the project folder 
    cd "C:\Users\Administrator\Documents\1SPACE\Website\esa-website"
  2. Install dependencies (first time only) This downloads the libraries into a node_modules folder. It takes 1–3 minutes. 
    npm install
  3. Start the development server 
    npm run dev
    You should see Ready and Local: http://localhost:3000.
  4. Open the site Go to http://localhost:3000 in your browser. Try the member directory, publications and the seed data dashboard.
  5. Stop the server Press Ctrl + C in the terminal.
Port already in use? Run on another port: npm run dev -- --port 3100, then open http://localhost:3100.
View on your phone: the terminal also shows a Network: address such as http://192.168.x.x:3000. Open it on a phone connected to the same Wi-Fi. Windows Firewall may ask you to allow Node.js.

3. Production build on your computer

This is exactly what Vercel runs. Doing it locally first catches errors before you deploy.

  1. Build 
    npm run build
    A successful build ends with a route list and a line like Generating static pages (101/101). TypeScript errors stop the build and show the file and line.
  2. Start the production server 
    npm start
    Open http://localhost:3000. This is the fast, optimised version of the site.
  3. Optional: check quality In Chrome, open DevTools (F12) → Lighthouse → Mobile → Analyze. The Phase 1 target (N2) is a mobile score of 85 or more.

Hosting on a local server or office PC

To keep the site running on a Windows machine on ESA's network, build once, then run npm start. To keep it running after the terminal closes, use a process manager:

npm install -g pm2
pm2 start npm --name esa-website -- start
pm2 save
For a public website, Vercel (next sections) is simpler and safer than hosting on an office PC: it gives HTTPS, backups of every deployment, and a global CDN without maintenance.

4. Deploy on Vercel: GitHub method (recommended)

With this method, every change you push to GitHub is deployed automatically, and every version can be rolled back.

  1. Create an empty repository on GitHub On github.com click New repository, name it esa-website, choose Private, and do not add a README. Click Create repository.
  2. Push the project from your computer 
    cd "C:\Users\Administrator\Documents\1SPACE\Website\esa-website"
git init
git add .
git commit -m "ESA website v1"
git branch -M main
git remote add origin https://github.com/YOUR-ACCOUNT/esa-website.git
git push -u origin main
    The included .gitignore already excludes node_modules and .next, so only source files are uploaded.
  3. Import the project into Vercel Sign in at vercel.com → Add New… → Project → Continue with GitHub → authorise access → choose esa-website → Import.
  4. Check the settings Vercel detects Next.js automatically. Leave the defaults:
    SettingValue
    Framework PresetNext.js
    Root Directory./ (if you pushed the parent Website folder instead, set it to esa-website)
    Node.js Version22.x or 24.x (Project Settings → Build and Deployment)
  5. Add the environment variable Under Environment Variables add SITE_URL = your final address, for example https://esa-website.vercel.app. (See section 6.)
  6. Click Deploy The build takes about 1–2 minutes. When it finishes you get a live address like https://esa-website.vercel.app.

5. Deploy on Vercel: CLI method

Use this to deploy straight from your computer without GitHub. Good for a quick preview link to share with ESA reviewers.

  1. Install the Vercel CLI 
    npm install -g vercel
  2. Log in 
    vercel login
    Choose your login method; a browser window opens to confirm.
  3. Deploy a preview 
    cd "C:\Users\Administrator\Documents\1SPACE\Website\esa-website"
vercel
    Answer the questions: Set up and deploy? Y · choose your scope/team · Link to existing project? N · project name esa-website · directory ./ · keep the detected Next.js settings. You get a preview URL.
  4. Add the environment variable 
    vercel env add SITE_URL production
    Paste the production address when asked.
  5. Deploy to production 
    vercel --prod

Preview deployments

Every vercel run (or every GitHub branch / pull request) gets its own URL. Use these for ESA review rounds without touching the live site.

Rollback

In the Vercel dashboard → Deployments, open any earlier deployment → ⋯ → Promote to Production (or Instant Rollback).

6. Custom domain and environment variables

Environment variables

NameExampleUsed for
SITE_URLhttps://www.ethiopianseedassociation.orgPage metadata, sitemap.xml and robots.txt. No trailing slash.

After changing an environment variable in Vercel, redeploy (Deployments → latest → Redeploy) for it to take effect.

The domain above is an example only. Use the domain ESA registers in its own name.

Connect ESA's domain

  1. Add the domain in Vercel Project → Settings → Domains → enter the domain (e.g. www.your-domain.org) → Add.
  2. Create the DNS records at your domain registrar Vercel shows the exact records to add. Typically:
    TypeNameValue
    A@ (root domain)the IP address Vercel shows
    CNAMEwwwthe CNAME target Vercel shows
    Always copy the values from your Vercel dashboard, as they can change.
  3. Wait for verification DNS changes take from a few minutes to 48 hours. Vercel issues the HTTPS certificate automatically once the domain points to it.
  4. Update SITE_URL to the new domain and redeploy.

9. Troubleshooting

ProblemFix
'npm' is not recognizedNode.js is not installed or the terminal was open before installing. Install Node.js, then open a new terminal.
Port 3000 is in useAnother app uses the port. Run npm run dev -- --port 3100, or close the other app.
Build fails with a TypeScript errorThe message names the file and line. Fix it, then run npm run build again. A missing comma or quote in content.ts is the usual cause.
Fonts fail to download during buildThe build fetches Google Fonts. Check your internet connection or proxy and retry.
Image not showingPaths are case-sensitive on Vercel. /images/news/Photo.JPG and /images/news/photo.jpg are different files.
Strange errors after updatesDelete the .next folder and run npm run build again. If needed, also delete node_modules and run npm install.
Vercel build fails but local build worksOpen the failed deployment → Build Logs. Check the Node.js version (22.x or 24.x) and that all files, including images, were committed.
Domain shows "Invalid Configuration"The DNS records don't match yet. Re-check them against Vercel's Domains page and allow time to propagate.
